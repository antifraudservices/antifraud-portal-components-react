# Changelog

## 0.4.5 - 2026-11-20

- Pin the published Antifraud data contracts that supply catalogue draft
  parsing and listing identity.

## 0.4.4 - 2026-11-20

- Add collapsible service activation cards with service-specific terms,
  authoritative price quotes, configurable payment options, and per-service
  activation, checkout and invoice status.

- Let the host accept photo attachments from each reviewed product or service.
- Keep public cards distinct when publishers or offering types share an ID.
- Add a reusable catalogue review form with per-entry review and a single
  publication action for the completed batch.

## 0.4.3

- Add a controlled public offering directory with sector/category filters
  before optional availability geography, search, grid/list views and one card
  per product. Seller offers distinguish eligibility, delivery, operation and
  support. Presentation never verifies an organisation or grants access.

## 0.4.2

- Add controlled generic credential QR capture with complete manual input, explicit host verification, bounded local PNG/JPEG/inert SVG images and camera cleanup. Share camera/jsQR primitives with existing professional profile capture; capture alone conveys no verification or authority.

- Validate all 65 component cases, strict typecheck and build. A separate real
  browser diagnostic decodes the official SHC example as SVG, PNG, JPEG and a
  synthetic video stream into its complete numeric value, without mocking the
  QR decoders. This establishes capture behavior, not physical-camera support
  or a clinical portal journey.

## 0.4.1 - 2026-11-17

- Pin public Common UI 1.3.1. The complete 49-case suite, strict typecheck and
  build passed against the exact archive now published as Common 1.3.1;
  release metadata preserves the same compiled component bytes.

- Keep host-provided individual details, controller details and private-evidence
  forms inside their corresponding identity steps. Optional content slots reuse
  the existing presentation without adding authentication or persistence.
  Eight focused tests and uncached typechecking pass.

## 0.4.0 - 2026-11-14

- Pin public Common UI 1.3.0 for the controlled portal renderers and neutral
  theme aliases.

- Include the three existing workforce compatibility cases in the normal test
  command because the deprecated component remains publicly exported. Retain
  the optional focused command; this changes no runtime or public API. Earlier
  44-case results excluded this suite and are not full public-surface coverage.
  The full default suite now passes 47 cases in 13 suites, with strict typecheck,
  build and source/emitted privacy checks passing.

- Add controlled recipient activation and existing-professional profile panels,
  preserving invitation/evidence separation, host resolution and profile
  selection before PIN enrollment. Reuse the neutral Common profile target and
  real QR decoder; media capture requires an explicit action and cleanup.
  Nine focused cases and the full typecheck pass; no browser authority or
  persistence is introduced.

- Own a neutral subject-access request panel with host-provided locator,
  resolved-target, section and request-status state. Unresolved targets and
  empty section selections cannot request access; pending state grants none.
  Two controlled UI cases pass, with no I/O or product dependency.

- Own the neutral identity/entity entry form and controlled evidence workspace,
  preserving distinct dependent/controller fields, optional paired identifiers,
  selected contact requirements and separate document inputs. Evidence routes
  remain host intentions and pending readback remains pending. Export both
  independently with neutral styles; six new and four retained identity tests
  and the full typecheck pass. No application authority or storage is added.

## 0.3.0 - 2026-11-08

- Add one controlled device-assistance preferences surface with independently
  supplied enablement, availability, preparation and detail state. Keep opt-out
  possible after a runtime becomes unavailable. Preparation requires an
  explicit click and an enabled, available, idle feature.
- Keep runtime detection, models, downloads, device storage and all permission
  decisions in application adapters. Export the component independently.
- Supply an independent stylesheet. The current renderer uses web DOM;
  sharing its controlled state contract does not implement a native renderer.
- Four component cases, package hygiene, typecheck and build pass. Host browser
  acceptance separately verifies phone-authenticated preferences and reloads.

## 0.2.1 - 2026-11-06
